# LightGBM Hybrid Classifier — Design Spec

**Date:** 2026-05-30
**Status:** Approved
**Goal:** Improve `detection_score` from 1477 → 2500+ by replacing the IVF full probe with a cost-aware LightGBM model for ambiguous cases.

---

## 1. Problem

Current local benchmark (`test/results.json`):

```
FP=76, FN=81, E=319  (E = FP + 3×FN)
detection_score = 1477  (target: 3000)
p99_score       = 3000  (maxed — do not regress)
final_score     = 4477  (target: 6000)
```

Root cause: IVF fast probe (nprobe=8) returns `fraud_count=2 or 3` for ~15-20% of requests. These are sent to full probe (nprobe=24), which applies a hard threshold (`count >= 3 → fraud`). The hard threshold ignores feature structure and the asymmetric cost (FN costs 3× more than FP in the scoring formula).

---

## 2. Scoring Formula

```
E = FP + 3×FN + 5×http_errors
absolute_penalty = 300 × log10(1 + E)
detection_score  = rate_component − absolute_penalty
```

**Bayes-optimal threshold for asymmetric cost:**
- Cost ratio: FN/FP = 3
- Optimal threshold: P(fraud) ≥ 1/(1+3) = **0.25**
- Standard 0.5 threshold is suboptimal — accepts too many FNs.

---

## 3. Architecture

```
request
  └─ IVF fast probe (nprobe=8)
        │
   fraud_count
        ├─ 0 or 1  →  approved  (certain legit)
        ├─ 4 or 5  →  denied    (certain fraud)
        └─ 2 or 3  →  LightGBM
                          │
                    P(fraud) ≥ 0.25  →  denied  (return count=3)
                    P(fraud) < 0.25  →  approved (return count=2)
```

**Full probe (nprobe=24) is eliminated from the hot path.** LightGBM replaces it for all ambiguous cases. The `FULL_NPROBE` constant is retained for array sizing but never used as a probe argument at runtime.

## 4. Training (`tools/train_model.py`)

### 4.1 Class weight

Add `class_weight={0: 1, 1: 3}` to `LGBMClassifier`. This encodes the scoring cost directly into the loss function — the model learns to minimize E = FP + 3×FN, not accuracy.

```python
model = lgb.LGBMClassifier(
    n_estimators=300,
    max_depth=6,
    num_leaves=63,
    learning_rate=0.05,
    random_state=42,
    n_jobs=-1,
    class_weight={0: 1, 1: 3},
)
```

### 4.2 Validation assertions

Replace hard threshold assertions with E-score assertion on validation set using threshold=0.25:

```python
# threshold=0.25 (cost-optimal)
pred_fraud = probs >= 0.25
fp_count = int(((pred_fraud) & (y_val == 0)).sum())
fn_count = int(((~pred_fraud) & (y_val == 1)).sum())
E_val = fp_count + 3 * fn_count
print(f"Val E (FP+3×FN at t=0.25): {E_val}  (FP={fp_count}, FN={fn_count})")
assert auc >= 0.99, f"AUC {auc:.4f} < 0.99"
assert E_val < 200, f"E={E_val} >= 200 on val set"
```

### 5.2 `src/fraud/knn.rs` — `knn5_ivf`

```rust
pub fn knn5_ivf(q: &[f32; 14], ds: &Dataset) -> u8 {
    let fast = probe(q, ds, FAST_NPROBE);
    let fraud_count = count_fraud(fast);
    if fraud_count == 2 || fraud_count == 3 {
        let q_f64: [f64; 14] = std::array::from_fn(|i| q[i] as f64);
        let p_fraud = super::model_gen::sigmoid(super::model_gen::score(&q_f64));
        if p_fraud >= 0.25 { 3 } else { 2 }
    } else {
        fraud_count as u8
    }
}
```

**Notes:**
- `f32 → f64` cast is lossless (f64 has strictly more precision).
- `model_gen::score()` returns log-odds (f64); `model_gen::sigmoid()` converts to P(fraud).
- Returns `3` (denied) or `2` (approved) to preserve existing response mapping in `response.rs`.
- `Cargo.toml` unchanged — no new dependencies.

## 7. Validation Sequence

```bash
uv run tools/train_model.py    # retrain + generate model_gen.rs (~15min)
cargo test                      # all tests pass, no regressions
uv run tools/eval_recall.py    # FP/FN vs brute-force
make bench                      # gate: detection_score > 2000, p99_score = 3000

```

**Regression gate:** `p99_score` must remain 3000. Any regression in latency means LightGBM is too slow for the ambiguous case rate.
